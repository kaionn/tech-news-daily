🧠 影響範囲を測る情報(ダウンロード数・配布期間・被害端末数)がPhorionの記事には一切なく、この分析はEDRベンダー1社の単独調査にとどまる。macOSでは`systemsetup -getremotelogin`の権限不足チェックが失敗してもスクリプトが終了コード0で抜けるため、Remote Loginが実際には有効化されずバックドアが機能しないケースが多かった可能性がある。ただし鍵の追記とLaunchAgentの設置自体は実行されており、後日何らかの経路でSSHが有効化されれば攻撃は成立する。AI開発ツールのサプライチェーンが実際に狙われた事例として、配布経路の検証体制を見直す材料にはなるだろう。
  • 影響を受けたのはClaude Code拡張機能v2.1.313。NodeロードからIIFEが即時発火し`activate`呼び出し前にSSH鍵を書き込むため、ユーザー操作は不要

  • ビーコンは平文HTTP(ポート8099)で環境変数の「名前」のみを送信し値は送らない。CursorはNPM・VS Code双方のレジストリから該当バージョンを削除済み

Azure API Connectionsに5件のクロステナント脆弱性、報奨金は累計20万ドル

  • `DynamicInvoke`のパストラバーサルで他テナントのKey Vaultシークレットを読み取り可能、`DynamicList`など同系エンドポイントでAzure SQLへの書き込みも可能だった

Go、Linuxカーネルのtcp UAF(CVE-2026-98432)対策で`GODEBUG=multipathtcp=0`を案内

GoチームはCVE-2026-98432(LinuxカーネルIPv4 TCP処理のuse-after-free)について、Go 1.24以降はlistenソケットでMultipath TCP(MPTCP)がデフォルト有効なため、Anthropicが報告したMPTCPリスナー経由のRCEエクスプロイトが成立しうると案内した。回避策として実行時は`GODEBUG=multipathtcp=0`、ビルド時は`go.mod`への`godebug multipathtcp=0`追記、個別ソケットでは`net.Dialer.SetMultipathTCP`等のAPIを使う方法を示すが、MPTCPを使わない経路でも同種の脆弱性が成立する可能性があるため、本質的な対策はカーネルの修正版への更新だとしている。
  • Go側の既定動作変更は時期尚早と判断し、議論はgo.dev/issue/82717で継続中。プログラム単位の無効化は見落としがあれば無意味になる「脆弱な緩和策」と明記されている
  • 脆弱性自体はMPTCP固有ではなく、MPTCPリスナーを使わないシステムでも類似の攻撃が成立する可能性があるとGoチームは注記する
