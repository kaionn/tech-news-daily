DEEP DIVE: GPGME に二重解放の脆弱性（CVE-2026-129975）、メーラーや Samba まで影響

GnuPG プロジェクトは 2026-11-20、暗号ライブラリ GPGME の double free 脆弱性 CVE-2026-129975 を公表し、修正版 2.3.1（11-19 リリース）への更新を促した。GPGME は gpg コマンドを呼び出して鍵一覧や署名検証を行うラッパーで、Gpg4win、GnuPG Desktop、多くのメールクライアント、XMPP クライアント、Samba、Flatpak などが利用している。問題は、gpg の出力するステータス行や鍵一覧を読む 2 つの内部関数にある。これらは 1024 バイトのバッファを確保し、必要に応じて realloc で拡張する。ところが読み取りエラーなどで早期 return すると、コンテキストが解放済みポインタを保持したままになり、後続の処理で同じ領域を再度 free してしまう。トリガーは、極端に長いユーザー ID を持つ細工された OpenPGP 鍵である。署名付きデータや公開鍵を受け取る側が鍵をインポートするだけで到達しうる。開発元は、アプリからのデータ窃取（署名データ経由など）に悪用できると明言し、リモートコード実行も「排除できない」としている。発見者は Johan Carlsson。GitLab からの報告は 11-12 で、公開は当初 11-25 の予定だったが、GitLab が別のバグ対応で先に更新したため前倒しされた。
🧠 GPGME は「gpg を呼ぶだけの薄い層」と見なされがちだが、信頼されていない鍵を機械的にパースする入口でもある。メール受信のように外部入力を自動処理する構成では、ユーザー操作なしで到達する可能性が高く、深刻度は CVSS 表記以上に実環境依存だ。ただし公開時点で実証コードや悪用報告は確認できておらず、RCE は「可能性を否定できない」段階にとどまる。2.3.0 が未公開という事情もあり、ディストリビューションの追従状況を自分で確認するのが先決だ。
  • 2.3.0 より前の全 GPGME（共有・静的リンク問わず）が対象で、修正版は 2.3.1。古い版向けにはパッチも提供
  • 1024 バイトバッファの realloc 後、早期 return で古いポインタが残り二重解放に至る
  • GitLab 報告（11-12）から公開（11-20）まで 8 日。予定の 11-25 から 5 日前倒し
💡 Gpg4win やメールクライアント、GPGME 静的リンクのバイナリを配布・運用しているなら、2.3.1 以降への更新とベンダーの再ビルド有無を今日中に確認してほしい。

Upload2Shell: Ghostscript の Type 1 フォント UAF（CVE-2026-125396）で CUPS や WordPress プラグインが RCE に

Ghostscript の Type 1 フォントローダーにある use-after-free により、細工した文書が -dSAFER サンドボックスを抜け、レンダリングプロセスの権限で任意コマンドを実行できる。PostScript/PDF/画像の変換を内部で Ghostscript に任せる製品が連鎖的に影響を受け、Debian 13 の CUPS、Roundcube、Plesk、WordPress プラグイン（Forminator、Essential Addons for Elementor）、MediaWiki、DokuWiki などで再現が確認された。匿名アップロードや公開フォームだけで攻撃できる構成もある。上流は 10.08.0 で修正済みで、Debian と Ubuntu はバックポートを提供している。
  • 検証は Ghostscript 10.05.1 で実施。修正は上流 10.08.0、Debian 13 は 10.05.1~dfsg-1+deb13u3
  • 実行権限は CUPS で lp、Web アプリ系で www-data。WordPress Core は別 CVE-2026-65640（7.0.0〜7.0.3、6.9.0〜6.9.6）
  • Roundcube は画像処理経路を CVE-2026-114727 で修正
💡 アップロードされた PDF や画像を ImageMagick 経由などで処理しているサービスは、Ghostscript が間接依存に入っていないかを gs --version と依存ツリーで確認すること。

Valkey 9.2: Sorted Set の skiplist を B+ 木に置換し、メンバーあたり最大 43% 省メモリ

  • Graviton3 64 コアで ZADD +105%、ZREM +76%、ZCOUNT +27%。PR ブランチでの計測で、マージ後の再計測ではない
