GitHub Actions を狙う大規模サプライチェーン攻撃、囮 PR は 6 万超のリポジトリに

GMO Flatt Security は、11 月 10〜12 日に確認された GitHub Actions 狙いの攻撃を報告した。「docs: dependency audit notes」という題の囮 PR が `wfx-docs` ブランチから送られ、乗っ取られたとみられるアカウントが使われている。続けて既存ワークフローへのステップ追加や、`package.json` の postinstall 経由で情報窃取スクリプトを実行させる変更が入る。CI 内のシークレット、AWS・Azure・GCP の認証情報、AI プロバイダの API キー、SSH/GPG 鍵、OIDC トークンが収集され、tgz にまとめて IP 直指定のエンドポイントか Telegram Bot API へ送信された。
  • 囮 PR が作られたリポジトリは 6 万超。コミットメッセージは「ci: refresh build cache」「chore: add ci helper」など
  • AWS の IAM ロール信頼ポリシーや Azure のフェデレーション資格情報の改変も試みており、キーのローテーションだけでは不十分
  • PR タイトル・ブランチ名（chore/ + ランダム 8 文字）で痕跡を検索し、該当時は CI 環境を隔離して全資格情報を再発行
💡 GitHub 上に公開リポジトリや CI を持つなら、過去 3 日分の PR とワークフロー変更を検索し、クラウド側の信頼設定の差分も確認すること。

  • `DropGuard`、`bool::toggle`、`str::trim_prefix`/`trim_suffix`、`Vec::from_fn` などの API も安定化

22 年前から存在した PostgreSQL の型混同を RCE に発展させた解析（CVE-2026-6460）

`ALTER TYPE ... ALTER ATTRIBUTE` は複合型の属性型を変えても、プリペアド文が保持する既存のバイナリ値を書き換えない。その結果、16 バイトの UUID が `bytea` として読まれ、先頭バイトが拡張オブジェクトのヘッダとポインタとして解釈される。この値を偽造して実行を乗っ取る。
  • 可変な行型の挙動は 2004 年、悪用された拡張オブジェクトのコールバックは 2015 年のコミットに由来
  • 権限の低いログインロールでクラッシュを起こせる。修正は 11 月 9 日の更新（新規 52 CVE 規模）に含まれる
