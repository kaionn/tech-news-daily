DEEP DIVE: Optimizely Web 経由で 178 組織にマルウェア配信、Zoom・GitLab・BBC も被害

11月16日、実験プラットフォーム Optimizely Web の顧客プロジェクトの「Project JavaScript」欄に悪意あるコードが書き込まれ、信頼された Optimizely の CDN から各サイトの訪問者へ配信された。被害サイト側のサーバーやコードは侵害されていない。Report URI の調査では、確認できた 1,611 個のスニペットのうち 188 個（178 組織）が感染し、Zoom、BBC、CNN、Salesforce、GitLab、IKEA、HSBC、Equifax などが含まれた。ペイロードは当日 26 回作り直され、暗号資産アドレスのすり替え、フォームからのカード番号・CVV の窃取、Cookie とスクリーンショットの送信を行う。さらに iPhone 向けに Coruna と DarkSword のエクスプロイトチェーンを隠し iframe で読み込み、iOS 18.6 以前では 60 秒ごとにページを再読み込みした。攻撃者のウォレットへの着金は 19:25 UTC 時点で約 7,040 ドルで、当日中に取引所へ送金された。書き込み権限をどう得たかは未特定で、Optimizely から Report URI への応答もなかった。UTC 21:52 の時点で感染が残るスニペットは 1 個まで減った。
🧠 サードパーティスクリプトの侵害が、自社の CI や本番を一切触らずに 178 組織へ届いた。この構造は特定ベンダーの問題ではなく、タグ配信全般に当てはまる。ただし著者は CSP 製品を販売する会社で、「製品なら検知できた」という記述は独立した検証ではない。侵入経路が未特定の間は、顧客側の認証情報流出か Optimizely 側の侵害かを区別できない点も留保すべきだ。
  • 感染 188 スニペット / 178 組織。最多は金融 32、テクノロジー 23、小売 20
  • CSP を調べた 256 組織のうち、ペイロードを完全に遮断できたのは 24（15%）。許可ドメインの指定より厳格な script-src が効き、'strict-dynamic' と 'unsafe-eval' が防御を崩した
  • iOS 18.7.3 以降 / 26.3 以降で更新済みなら Coruna・DarkSword の対象外
💡 Optimizely Web を使う組織は Project JavaScript に 1688360.cc や atob( がないか確認し、ユーザー・API トークンをローテーションすること。11月16日に自社フォームへ入力されたカード情報は漏えい扱いが妥当。

Microsoft、M365 大規模障害の原因は 7 月の修正に混入した不具合と説明

Microsoft は Exchange Online / Outlook の障害について、7月に M365 のネットワークゲートウェイへ入れた変更が原因と説明した。変更には Windows 内部プロセスのロック競合があり、CPU とメモリを使い切る。負荷が低い間は潜伏し、Teams が Exchange を支えるプライマリゲートウェイへフェイルオーバーした際に顕在化した。同時にゲートウェイ容量の約 14% が停止しており、再ルーティングで障害が全体へ波及した。ロード試験はコア数の少ない弱いハードウェアを中心にしており、コア数が多いほど競合が悪化する点を見逃していた。
  • 最悪時にサーバーの 80% 超が応答せず、初回サポートケースから緩和策適用まで約 15 時間
  • 不具合は 3 か月前の変更で、単純なロールバックができず既知の正常状態へ戻すパッチを作成して順次適用
  • 最終報告書は 11月20日に公開予定
💡 自社の SLA 設計では、ロック競合のようなコア数依存の不具合が本番ハードウェアでしか出ない前提で試験構成を見直す価値がある。
