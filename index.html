DEEP DIVE: Outlook.com が DMARC 未設定ドメインのメールを黙って拒否し始めた

MailRoute の報告によると、11 月 5 日から Outlook.com、Hotmail、Live、MSN が、DMARC レコードを持たないドメインのメールの一部を拒否している。Microsoft の高ボリューム送信者規則（2025 年 5 月、1 日 5,000 通超が対象）とは別で、小規模・低頻度の送信者にも及ぶ。ただし Microsoft はこの変更を告知しておらず、11 月 6 日時点で postmaster への通知もサービス正常性の掲示もない。バウンスは一部のメッセージだけで起きるため、「届いたから大丈夫」とは判断できない。エラーは「550 5.7.1 Message rejected: Message lacks SPF/DKIM/DMARC Auth Records」で、末尾の AS コードはメッセージごとの ID だ。初日は AS コードなしの 550 5.7.1 も出ていた。従来のバルク送信者向け拒否は 550 5.7.515 で、失敗した検査が一覧で返る。対処は `dig +short TXT _dmarc.yourdomain.com` で DMARC の有無を確認し、無ければ `_dmarc` の TXT に `v=DMARC1; p=none` を追加する。p=none は他の受信側の挙動を変えない。さらに From ドメインで SPF か DKIM が通り、アラインメントが取れている必要がある。Microsoft 365 では既定の DKIM 署名が onmicrosoft.com のドメインなので、自社ドメインの DKIM を有効にしないと DMARC に寄与しない。
🧠 Google と Yahoo の 2024 年の要件変更と同じ流れで、受信側が認証を必須化する方向は止まらないだろう。一方で今回は公式告知がなく、規則として固定されたのか、段階導入中の実験なのかは分からない。単一の報告ブログが根拠なので、自社ドメインのバウンスログで 550 5.7.1 を実測するまでは断定を避けたい。確認に数分、p=none の追加は他社宛配信に影響しないため、様子見の理由は薄い。
  • 11 月 5 日以降、DMARC を持たない送信元ドメインのメールの一部が 550 5.7.1 で拒否される
  • 最低限の対処は `_dmarc` TXT に `v=DMARC1; p=none` を追加。SPF/DKIM のアラインメントも必要
  • Microsoft 365 は既定署名が onmicrosoft.com のため、独自ドメインの DKIM 有効化が必要
💡 自社ドメインから Outlook.com 宛にメールを送るサービスを運用しているなら、今日中に DMARC レコードの有無を確認すること。

systemd が Rust サポートをマージ、まずはリーフコンポーネントから

Brauner 氏と Poettering 氏の投稿で、systemd 本体に Rust を取り込んだことが示された。180 以上あるバイナリのうち、単体のリーフコンポーネントでのみ Rust を認め、中核の libsystemd-shared.so は対象外とする。Rust なしのビルドは引き続きサポートされる。
  • ビルドは Meson のまま Cargo を使わず、no-std Rust と独自の失敗可能なアロケータで libc のみにリンク。他の依存は dlopen()
  • 中核への採用を阻むのは、安定した共有ライブラリ ABI（rfcs issue 600）と fd 中心のファイル操作

  • build / load / push などは 501 を返し、docker build は使えない（nspawn build は可）
