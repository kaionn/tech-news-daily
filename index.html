DEEP DIVE: GitHub Copilot Fusion正式リリース、タスクに応じてAIモデルを自動選択・組み合わせ

GitHubは10月28日からサンフランシスコで開催した年次イベント「GitHub Universe 2026」で新機能「Copilot Fusion」を発表し、同日中に正式リリースした。従来のCopilotはユーザーが単一のAIモデルを都度選び、タスクの難易度や予算に応じて自分で切り替える必要があった。Fusionはこの選択自体を自動化し、推論・コード生成・デバッグ・ツール利用の必要度を判定した上で、単一モデルだけで解くか複数モデルを組み合わせて解くかを動的に決める。組み合わせ方には3パターンがある。「Single」は選定した1モデルのみで完結させる方式、「Cascade」は効率重視の軽量モデルがまず草案を作り、品質チェック用モデルが検証し、必要と判断した場合のみより高性能なモデルへ処理をエスカレーションする方式、「Critique」は1モデルが草案を作り、別系統のモデルファミリーが独立にレビューし、草案側がそのフィードバックを基に1回だけ修正する方式だ。さらに用途別に「Standard」「High」「Max」「Fast」の4つのeffortレベルを用意し、コスト・品質・待ち時間のバランスを調整できるようにした。Fastは自動選択のみでユーザーは選べない。Standard枠内では、ローカルにインストールした軽量モデル「MAI Code 1.1 Flash」や「Qwen3.8 Flash Next」をパブリックプレビューとして試すこともできる。
🧠 モデル選択を自動化するという方向性自体は妥当で、チームごとに「どのモデルを使うか」を議論する時間を減らせる可能性はある。ただし公式発表にはベンチマークやコスト削減率の具体的な数値が一切示されておらず、Cascadeのエスカレーション判定がどの程度の精度で「もっと良いモデルが必要か」を見極められるのかは未検証のままだ。判定を誤って毎回Maxへエスカレーションすれば、むしろ単一モデル運用よりコストが増える可能性もあり、実際の効果は利用チームからの実測レポートを待つ必要がある。
  • 3つのオーケストレーション方式(Single/Cascade/Critique)と4つのeffortレベル(Standard/High/Max/Fast)を用意、Fastはユーザーが選択不可で自動適用のみ
  • Standard枠ではローカル実行の軽量モデル「MAI Code 1.1 Flash」「Qwen3.8 Flash Next」をパブリックプレビューとして利用可能
  • 発表はGitHub Universe 2026(10月28日〜29日、サンフランシスコ)に合わせて行われ同日中に正式リリース(GA)。使用するクラウドモデル名やベンチマーク数値は非公開
💡 モデル選定の手間をFusionに委ねられる一方、effortレベルの設定次第でコストが跳ね上がるリスクもあるため、導入初期はコスト上限や使用量ダッシュボードを必ず確認すべきだ。

研究者らは、異なるモダリティで別々に訓練したモデルがスケールに伴い同じ世界表象へ収束するという「プラトン的表象仮説(PRH)」について、これまで証明がなかった状態から、JEPA(Joint-Embedding Predictive Architecture)の枠組みで初めて定理として証明したと報告した。同一シーンの2視点のような「良いビュー」を正例ペアに使うJEPAは、モダリティ数に関わらず単一の回転変換を除いて同じ表象を学習するという。次トークン予測は1つの文書の一部を使う「悪いビュー」のJEPAとみなせ、言語モデルが画像表象とスケールでしか整合しない理由を説明するとしている。

符号付き32bit除算でコンパイラに勝つ、不要な補正ステップを削り最大20%高速化

  • Intel Emerald Rapidsでは除数7・60・365でレイテンシが10サイクルから8サイクルに短縮、Clangではスループットが20%以上向上。Apple M4でも除数7でスループット0.34→0.29ns(約12%改善)
  • 実行時除数向けのfastmodライブラリも分岐なしの符号付き64bit乗算に変更し、Intel/GCC環境でスループットが3.07nsから0.77nsへ改善。著者は「なぜコンパイラがこれをやらないのか分からない」と述べている
