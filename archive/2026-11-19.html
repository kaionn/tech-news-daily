DEEP DIVE: nginx の HTTP/2 実装に認証不要の RCE 脆弱性 2 件、1.31.8 までが影響

Wiz Research は nginx の HTTP/2 処理に CVE-2026-123633 と CVE-2026-123007 の 2 件の重大な脆弱性を公開した。いずれも CVSS 4.0 で 9.2 である。前者は、リクエストを処理していない HTTP/2 接続が「再利用可能」リストに載ったまま、新しいリクエスト開始時にリストから外されないことで生じる use-after-free だ。空きコネクションスロットが逼迫すると、nginx が実行中のリクエストを抱えた接続を閉じ、リクエストがまだ使っているメモリを解放してしまう。後者は、キャンセルされたストリームが送信ウィンドウの余剰分を返す際にプロトコル上限を確認せず、境界チェックで値がラップして負の長さになり、TLS 送信経路で範囲外メモリコピーに至る整数アンダーフローである。影響範囲は 123633 が 1.19.7〜1.31.8、123007 が 1.9.5〜1.31.8 と広く、後者は HTTP/2 を有効にした既定構成、つまり静的ファイル配信だけの構成でも成立する。Wiz は公式ビルド 1.31.7 と 1.31.8 で、64 ビット環境の HTTP/2 over TLS 経由で ASLR を回避した RCE を実機検証済みとしている。修正版は stable の 1.30.7 と mainline の 1.31.9 で、Wiz は PoC を公開していない。現時点で実環境での悪用は報告されていない。
🧠 nginx は CDN の背後からロードバランサ、リバースプロキシまで置かれる場所が広く、HTTP/2 を既定で有効にしている環境も多い。その点で、静的配信だけの構成も対象になる 123007 は棚卸しの優先度が高い。ただし ALB の既定ターゲットグループや gRPC なしの CloudFront のように、nginx まで HTTP/1.1 でしか届かない経路では到達性が下がる（DevelopersIO の整理による）。パッチが出た直後の「PoC 非公開」は、リバースエンジニアリングで再現されるまでの猶予にすぎないため、実環境での悪用が確認されていない今のうちに更新するのが妥当だろう。
  • CVE-2026-123007: キャンセル済みストリームの送信ウィンドウ返却で整数アンダーフロー。HTTP/2 有効なら既定構成でも到達可能（1.9.5〜1.31.8）
  • CVE-2026-123633: HTTP/2 接続の再利用リスト管理ミスによる use-after-free。HTTP/2 リバースプロキシで接続スロットが逼迫したときに発現（1.19.7〜1.31.8）
  • 修正は OSS 1.30.7 / 1.31.9、NGINX Plus は 37.0.7.1 / 37.2.0.1 ほか。更新できない場合は `http2 off;`（1.25.1 以降）で回避
💡 nginx で HTTP/2 を有効にしているなら、まず 1.30.7 / 1.31.9 へ更新し、更新できない間は http2 off で暫定回避すること。
