DEEP DIVE: 1Password、従業員の GitHub アカウント侵害からバックエンドに悪意あるコードを投入される

1Password は 11 月 19 日、従業員の社内 GitHub アカウントが攻撃者に使われた形跡の調査を始めた。攻撃者はそのアカウントでソースコードに到達し、バックエンドサービスへ悪意あるコードを push した。このコードを経由して、一部顧客の管理データが取得された。取得されたのは連絡先、アカウント・ユーザー ID、作成日時と最終サインイン日時、公開鍵、SRP パラメータ、招待・プロビジョニング・アカウント復旧メールに含まれるトークンなどである。加えて、非公開リポジトリのソースコードが複製され、インフラの秘密情報を保持する CI/CD システムにもアクセスされた。1Password は可能性のある認証情報をすべてローテーションした。保管庫とその項目、保管庫の鍵、復旧キー、アプリ・ブラウザ拡張は影響を受けていないという。トークン単体ではアクセスできず、SSO サインインかメールで届く 6 桁コードとの組み合わせが要る。この点を踏まえ、コードを 6 桁数字から 10 桁英数字へ延長した。影響を受けた顧客数は公表されていない。
🧠 保管庫が無傷という説明は、暗号設計の面では筋が通る。ただし今回の本質は製品の暗号ではなく、開発基盤の 1 アカウントから本番バックエンドに悪意あるコードが入った点にある。ブランチ保護や push 時のレビューがどこで破られたかは未公表で、再発防止の実効性はここが明かされるまで判断できない。顧客数が非公表なのも、現時点では評価を留保する材料だ。
  • 攻撃経路は従業員の GitHub アカウント → 悪意あるコードの push → バックエンドによる管理データ取得。ソースコード、CI/CD 経由でインフラ秘密情報にも到達
  • メール認証コードを 6 桁数字から 10 桁英数字へ変更し、盗まれたトークンの悪用に必要な総当たり量を増やした
  • 社内証拠では、露出したトークンによるアカウント乗っ取りは確認されていない。独立の専門家が封じ込めを検証中
💡 GitHub 組織を運用しているなら、従業員アカウントの権限と CI/CD の秘密情報の分離を点検すること。顧客側は 1Password を装う不審なメール・電話に注意する。

Scott Aaronson、AI 支援による計算量理論・数学の成果主張が相次ぐと報告

  • OpenAI の論文（11 月 24 日付）は ω = 9/4 を主張。1960 年代末の Strassen の ω < 3 から続く問題
  • Riemann 予想の Lean 形式化は約 1,700 万行から約 30 万行へ圧縮されたと、コメント欄が報告（未検証）
  • Yupan Liu が AI 支援で QIP(2) = PSPACE を arXiv に投稿

Armin Ronacher「Rust の Mutex の lock poisoning を廃止せよ」

  • 提案は std::sync::nonpoison を安定化して既定にし、必要な人向けに Poison<T> ラッパーを用意すること
