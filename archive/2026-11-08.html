DEEP DIVE: Alpine Linux の openssh-server にパスワード認証バイパス、257 バイト超のパスワードで突破

Alpine Linux は 11 月 5 日、openssh-server のパスワード認証を無効のまま通過できる脆弱性を公表した。PAM を使わない構成では、sshd が入力パスワードを crypt() でハッシュ化し、保存済みハッシュと比較して認証する。musl の crypt() は 256 バイトを超える入力に対し、エラー値として文字列 "*" を返す。パスワード未設定のアカウントも /etc/shadow に "*" を保存しているため、両者が一致して認証が通ってしまう。攻撃者に必要なのは 257〜1024 バイトのパスワードを 1 回送ることだけだ。ただし成立には、PasswordAuthentication が有効であること、"*" のアカウント（root や alpine など）が存在すること、$5$ または $6$ ハッシュを持つ別のローカルアカウントがあることが揃う必要がある。影響は Alpine 3.21〜3.24 と edge、サポート終了済みの 3.16〜3.20、3.18.11〜3.24.3 の tiny-cloud イメージに及ぶ。修正版は 3.21.10、3.22.8、3.23.8、3.24.4 で、edge は 10.6_p2-r0。`apk upgrade -U -a` のあと `rc-service sshd restart` を実行する。更新できない場合は PasswordAuthentication を no にし、鍵ログインを確認してからセッションを閉じる。CVE は本稿時点で未割り当てだ。
🧠 原因は OpenSSH 本体ではなく、musl の crypt() が「失敗」と「ロック済みアカウント」を同じ文字列で表す設計にある。この種の番兵値の衝突は、他の libc 依存ソフトでも同じ形で出うる。軽量コンテナで Alpine の sshd を使い、パスワード認証を残している環境は多くないはずだが、tiny-cloud イメージは既定設定を確認するまで安全と言えない。未検証だが、/var/log/messages に root など無パスワードアカウントへのパスワードログイン成功が残っていれば、侵害済みとして扱うべきだ。
  • musl の crypt() が 256 バイト超でエラー値 "*" を返し、無パスワードアカウントの "*" と一致して認証成功
  • 修正版は 3.21.10 / 3.22.8 / 3.23.8 / 3.24.4、edge は 10.6_p2-r0。CVE は未割り当て
  • 回避策は PasswordAuthentication no。PAM 構成でも UsePAM no なら対象
💡 Alpine ベースのサーバーで sshd を動かしているなら、今すぐ apk upgrade するか、パスワード認証を切ること。

Discord、Electron を捨てて GPUI 製 Rust クライアントへ。RAM は約 70% 減

Discord がデスクトップ版を Electron から Rust 製クライアント（タスクマネージャー上の名称は Discord Phoenix）へ置き換えている。UI は Zed エディタの GPU 描画フレームワーク GPUI で、HTML を使わずに描く。Tauri は採用していない。モバイルは React Native をやめ、Web 版はロジックを WebAssembly へ移す。非公開テスト段階で、公開日は未定。
  • 2 アカウント同時ログインで 290.2MB。記事は Electron の 1GB 目安から約 70% 減と見積もる
  • コールドスタートでは Rust 版が約 1 秒でウィンドウ表示し、Electron は約 5 秒で UI に到達
  • 同一条件のベンチは未公開。早期ビルドのスナップショットである
💡 Electron アプリを抱えるチームは、メモリ比較の指標が「1GB を切るか」から変わりうる点を意識しておきたい。ただし数値は第三者の計測で、GPUI の成熟度は別問題だ。
